# 交友广场（Discover Plaza）设计方案

> 本文档描述交友广场功能的**后端**实现：数据模型、实体、REST 接口（统一 POST）、业务规则、数据访问与客户端对接。
> 涉及仓库：`only-talk-rs`（后端），前端交互见 `only-talk-app` 相关实现。

> **✅ 落地状态（2026-08）**：数据表 + rbatis 实体模型 + http_service 接口已实现，接口统一采用 **POST** 风格（弃用 RESTful 动词）。

## 1. 目标

为客户端提供「交友广场」能力：

- 用户可显式开关「允许被发现」，开启后才出现在广场
- 用户可设置「交友宣言」（motto）与一组「标签」（tag），并展示在广场
- 广场页分页浏览其他已开启用户（排除自身），按资料展示卡片
- 从广场可对目标用户发起好友请求
- 用户在自己的「交友广场」设置页编辑开关 / 宣言 / 标签

## 2. 背景与现状

- 已有 `user_info`（性别/年龄/地区/生日）与 `basic_user`（用户名/头像/简介/账号），**不做冗余快照**，资料一律通过 JOIN 获取。
- 现有 `user_cache` 为通用 JSON 缓存表，不重复占用。
- 广场功能需新增的专属信息只有三样：`允许被发现`、`交友宣言`、`标签`。

## 3. 数据模型（PostgreSQL）

### 3.1 `plaza_user_info`（广场用户信息，1:1 对用户）

以「用户 uuid」为主键（同 `user_info`）：

```sql
CREATE TABLE IF NOT EXISTS plaza_user_info (
    uuid uuid NOT NULL,                       -- 用户主键（= user.uuid）
    allow_discover bool DEFAULT false NOT NULL, -- 是否允许被发现(默认关闭=隐私优先)
    motto varchar(255) NULL,                  -- 交友宣言
    status int2 DEFAULT 0 NOT NULL,           -- 状态: 0-正常, 1-隐藏, 2-封禁
    created_at int8 NOT NULL,                 -- 创建时间(Unix秒)
    updated_at int8 NOT NULL,                 -- 更新时间(Unix秒)
    CONSTRAINT plaza_user_info_pk PRIMARY KEY (uuid)
);

CREATE INDEX IF NOT EXISTS idx_plaza_user_info_allow_updated
    ON public.plaza_user_info USING btree (allow_discover, updated_at);
```

> `(allow_discover, updated_at)` 组合索引服务广场流「按更新倒序 + 过滤开启用户」。

### 3.2 `plaza_user_tag`（用户广场标签，1 行 / 标签）

```sql
CREATE TABLE IF NOT EXISTS plaza_user_tag (
    id uuid NOT NULL,                         -- 主键
    user_uuid uuid NOT NULL,                  -- 所属用户
    tag varchar(32) NOT NULL,                 -- 标签内容(1-32字符)
    sort int4 DEFAULT 0 NOT NULL,             -- 展示顺序
    created_at int8 NOT NULL,                 -- 创建时间(Unix秒)
    CONSTRAINT plaza_user_tag_pk PRIMARY KEY (id),
    CONSTRAINT plaza_user_tag_unique UNIQUE (user_uuid, tag)
);

CREATE INDEX IF NOT EXISTS idx_plaza_user_tag_user ON public.plaza_user_tag USING btree (user_uuid);
CREATE INDEX IF NOT EXISTS idx_plaza_user_tag_tag  ON public.plaza_user_tag USING btree (tag);
```

> **「最多 100 个标签」不在 DDL 层强制**（PG 难以对行数做 CHECK），由应用层校验；后续大后期可加定时任务核查，当前仅做单次请求上限截断。

## 5. API 设计（全部 POST，弃用 RESTful）

模块：`crates/http_service/src/http_service/plaza_service/`，注册于 `http_service/mod.rs` 的 `configure_routes`：

```
.service(web::scope("/plaza").configure(init_plaza_service))
```

| 方法 | 路径 | 说明 | 请求体 | 返回 |
|---|---|---|---|---|
| POST | `/plaza/profile` | 我的广场设置（开关/宣言/标签） | `{}` | `PlazaProfileVO` |
| POST | `/plaza/profile/update` | 更新开关/宣言（懒创建 upsert） | `PlazaUpdateProfileDTO` | 空数据 |
| POST | `/plaza/tag/update` | 整组替换标签 | `PlazaUpdateTagsDTO` | 空数据 |
| POST | `/plaza/list` | 分页发现流 | `ReqList<PlazaListQuery>` | `PlazaListVO` |
| POST | `/plaza/user/{uuid}` | 单用户详情 | 空 | `PlazaUserVO` |

所有接口均从 JWT 中取当前用户 `uuid`（`get_uuid_from_header!`）；写接口仅能操作自己；`list` / `user` 排除或校验发现状态。

## 6. 业务规则

1. **允许被发现默认 `false`**，行不存在即视为未开启（隐私优先，用户主动开关）。
2. **懒创建**：`plaza_user_info` 行在用户首次调用 `/plaza/profile/update` 时插入（`uuid = 当前用户`, `status = 0`, 时间 = now）；否则 `update_by_map(uuid)`。无需预创建。
3. **标签规范化**（`/plaza/tag/update`）：逐项 `trim`、过滤空串、长度上限 32 字符、去重保序，单次截断到 100；事务内先 `delete_by_user` 再逐条 `insert`（`id=Uuid::now_v7()`，`sort=下标`，`created_at=now`）。
4. **广场流**（`/plaza/list`）：`allow_discover = true AND status = 0 AND uuid <> 当前用户`，`ORDER BY updated_at DESC`，`page_size` 截断到 `[1, 50]`，默认 20。
5. **筛选**（可选）：`gender`、`age_min`、`age_max` 按需拼进 WHERE（`ui.gender = ?`、`ui.age::int >= ?`、`ui.age::int <= ?`）。当前 `user_info` 性别/年龄无独立索引，数据量大时再补。
6. **时间戳**：统一 Unix 秒（`common::utils::time::get_now_time_stamp_as_secs`）。
7. **仅能看「可发现」用户**：`/plaza/user/{uuid}` 也过滤 `allow_discover=true AND status=0`，否则返回「不存在或不可发现」。

## 7. 数据访问要点

- `/plaza/list`：一次 JOIN 分页查询 + `count(*)` 求 total + 按页内 uuids 批量取标签（也可逐用户 `select_by_user`，页大小默认 20，开销可控）。
  ```sql
  SELECT pi.uuid, bu.username, bu.icon, bu.info,
         ui.gender, ui.age::int AS age, ui.address, pi.motto
  FROM plaza_user_info pi
  JOIN basic_user bu ON pi.uuid = bu.uuid
  LEFT JOIN user_info ui ON pi.uuid = ui.uuid
  WHERE pi.allow_discover = true AND pi.status = 0 AND pi.uuid <> ?
  ORDER BY pi.updated_at DESC LIMIT ? OFFSET ?
  ```
- `/plaza/profile`：`select_by_uuid(my)`，无行返回默认 `{ allow_discover:false, motto:None, tags:[] }`；标签 `select_by_user(my)`。
- `/plaza/profile/update`：事务内存在→更新，不存在→插入（懒创建）。
- `/plaza/tag/update`：事务 `delete_by_user(my)` + 逐条 `insert`。

## 8. 返回风格

- 读接口：service 返回 `Result<String, anyhow::Error>`，用 `CommonResponseRef::success_json(&vo)`（`code: 200`）序列化；controller 用 `respond_json_any!`。
- 写接口：controller `Ok` 返回 `CommonResponse::<bool>::success(true)`（`code: 200, data: true`，客户端 `parseData` 判定）；`Err` 返回 400 + `CommonResponseNoDataRef::error_json(&e.to_string())`。

## 9. 客户端对接（only-talk-app）

- `packages/services/src/plazaService/`：`get_plaza_users(pageNum,pageSize,query)` → `POST /plaza/list`；`get_plaza_profile`、`update_plaza_profile`、`update_plaza_tags`、`get_plaza_user` 对应各接口；统一经 `parseData`（`code === 200`）。
- `packages/types/src/plaza/`：`PlazaUser`、`PlazaListResult`、`PlazaProfile`、`PlazaUpdateProfileDTO`、`PlazaUpdateTagsDTO`、`PlazaListQuery`。
- 设置页「交友广场」Tab：允许被发现开关 / 交友宣言 / 标签编辑；保存后触发全局刷新。
- 广场页：卡片画廊 + 资料弹窗；弹窗「加好友」复用好友请求通道 `add_friend`（`add_type=plaza`），并对「已是好友 / 重复申请」给出区分提示。

## 10. 后续演进（未落地）

- **100 标签业务上限**：后续定时任务核查，当前仅单次请求截断。
- **筛选性能**：广场量大时给 `user_info(gender)`、`user_info(age)`（或组合）补索引。
- **冗余快照**：若广场接口投影重、压测偏慢，再考虑把 `username/icon/info/gender/age/address` 报名时快照进 `plaza_user_info`（当前坚持归一化 JOIN）。
- **广场拓展字段**（产品向）：`city`、`gender_pref`、`featured`、`weight` 等，按需再加。
