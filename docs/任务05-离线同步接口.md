## 2. 接口契约

### 2.1 请求

```
POST /session/sync
Headers: Authorization: <jwt>

{
  "mode": "incremental",      // "incremental"(默认, 可省) | "initial"
  "sessions": [],             // 空 = 服务端筛选全部有未同步的会话;
                              // 非空 = 仅拉指定会话(用于客户端 has_more 续拉)
  "limit": 100                // 单会话单次上限, 服务端 clamp 到 [1, 200]
}
```

### 2.2 响应

```json
{
  "code": 200,
  "data": {
    "server_time": 1758000000000,
    "sessions": [
      {
        "session_uuid": "3f2b...",
        "session_type": 1,
        "messages": [
          {
            "id": 12345,
            "nano_id": "V1StGXR8_Z5jdHi6B-myT",
            "session_uuid": "3f2b...",
            "session_type": 1,
            "send_user": "...",
            "recv_user": "...",
            "text_type": 1,
            "timestamp": 1757999999000,
            "raw": [104, 101, 108, 108, 111]
          }
        ],
        "next_cursor": 12345,
        "has_more": false,
        "truncated_by_window": false
      }
    ]
  }
}
```

### 2.3 关键语义（写死，避免实现歧义）

| 语义 | 规则 |
|------|------|
| 游标权威 | 拉取起点**永远是服务端 `user_session.synced_id`**，请求不带游标。客户端续拉 = 把该会话放进 `sessions` 再调一次；服务端游标未推进时会重拉已拉过的 —— **宁重勿漏**，客户端 `nano_id` 去重兜住 |
| 消息顺序 | 会话内按 `id` 升序，客户端可直接顺序入库 |
| 空响应终止 | 增量模式下**无消息的会话不输出**（`sessions` 为空即"同步完毕"），客户端以此终止循环 |
| `has_more` | `messages.len() == limit` 时为 true；客户端应继续拉该会话（先落库回报 `synced_id`，再把会话放入 `sessions` 重调） |
| `truncated_by_window` | 仅有消息因 7 天窗口被跳过时 true；**仅在 `has_more=false` 时探测**（还有更多可拉时无意义） |
| 群聊 `recv_user` | 填 `group_uuid` —— 客户端按 `session_type` 分流，与现有群消息处理链（`group_id` 路径）兼容 |
| `text_type` | 单聊为消息 `text_type`；群聊为 `msg_type`（两套值域不同，客户端按 `session_type` 解释） |

### 2.4 两模式

| | `incremental`（默认） | `initial` |
|---|---|---|
| 场景 | 重连同步 | 新设备 / 本地库清空 |
| 游标起点 | `user_session.synced_id` | 无视游标，每会话取**最新** limit 条（`order by id desc` 后反转） |
| 窗口 | `timestamp > boundary` 过滤 | 同左 |
| `has_more` | 正常返回 | **恒 false**（超出窗口的不再回溯，主方案 §8.4） |
| 依赖 | `user_session` 行存在（聚合建立） | 同左 —— 新设备登录时 `user_online` 聚合已建行，`synced_id=0` |

> `initial` 拉完后客户端照常回报 `synced_id`（= 每会话本批 max id），之后的重连即走增量。

## 3. 常量

`session_service/service.rs` 顶部：

```rust
/// 离线消息最大回溯窗口(天)。服务端计算, 不信任客户端时间(§8.1)。
const SYNC_WINDOW_DAYS: i64 = 7;
/// 单会话单次同步默认条数(主方案附录 B)。
const SYNC_DEFAULT_LIMIT: u32 = 100;
/// 单会话单次同步硬上限(防客户端传大值)。
const SYNC_MAX_LIMIT: u32 = 200;

fn window_boundary() -> i64 {
    chrono::Utc::now().timestamp_millis() - SYNC_WINDOW_DAYS * 24 * 3600 * 1000
}
```

> http_service 已依赖 `chrono`（workspace 有）。若团队希望可配置化，迁入 `app_config.toml` 的 `[session]` 段 —— 非必须，注释标注即可。

## 4. DTO（`session_service/dto.rs` 追加）

```rust
/// 同步请求
#[derive(Debug, Deserialize, Serialize)]
pub struct SyncRequestDTO {
    /// "incremental"(默认) | "initial"; 非法值按 incremental 处理
    pub mode: Option<String>,
    /// 指定会话(可空); 元素为 session_uuid 字符串
    pub sessions: Option<Vec<String>>,
    /// 单会话上限, 服务端 clamp [1, SYNC_MAX_LIMIT]
    pub limit: Option<u32>,
}

#[derive(Debug, Deserialize, Serialize)]
pub struct SyncMessageVO {
    pub id: i64,
    pub nano_id: String,
    pub session_uuid: String,
    /// 1-单聊 2-群聊: 客户端分流依据(与 text_type 值域解释联动)
    pub session_type: i16,
    pub send_user: String,
    /// 单聊: 接收方; 群聊: 即 group_uuid
    pub recv_user: String,
    /// 单聊: text_type; 群聊: msg_type
    pub text_type: u16,
    pub timestamp: i64,
    /// 消息内容(与现有接口同形态: 字节数组)
    pub raw: Vec<u8>,
}

#[derive(Debug, Deserialize, Serialize)]
pub struct SyncSessionVO {
    pub session_uuid: String,
    pub session_type: i16,
    /// 会话内按 id 升序
    pub messages: Vec<SyncMessageVO>,
    /// 本批最大消息 id; 客户端落库成功后经 /session/synced 回报
    pub next_cursor: i64,
    pub has_more: bool,
    pub truncated_by_window: bool,
}

#[derive(Debug, Deserialize, Serialize)]
pub struct SyncResponseVO {
    pub server_time: i64,
    pub sessions: Vec<SyncSessionVO>,
}
```

> **VO 字段名刻意与 `TextQuicMsg` / 客户端 `TextQuicMsgVo` 对齐**（`nano_id` / `raw` / `timestamp` / `send_user` / `recv_user` / `text_type`）—— 任务 07 的客户端切换可直接把 `SyncMessageVO` 喂给现有 `insert_chat_record` 处理链，改动最小。

```rust
/// 同步拉取: 游标 + 7 天窗口 + 升序(§8.1 核心查询, index-only scan 命中 idx_chat_msg_pull)。
#[rbatis::py_sql(
    "select * from chat_message_record
     where session_uuid = #{session_uuid} and id > #{cursor} and \"timestamp\" > #{boundary}
     order by id asc limit #{size}"
)]
async fn select_sync_inner(
    rb: &dyn Executor, session_uuid: &Uuid, cursor: i64, boundary: i64, size: u32,

pub async fn select_sync(
    rb: &dyn Executor, session_uuid: &Uuid, cursor: i64, boundary: i64, size: u32,
) -> rbatis::Result<Vec<ChatMessageRecord>> {
    Ok(Self::select_sync_inner(rb, session_uuid, cursor, boundary, size).await?)
}

/// initial 模式: 会话最新 N 条(窗口内), 取回后反转成升序。
#[rbatis::py_sql(
    "select * from chat_message_record
     where session_uuid = #{session_uuid} and \"timestamp\" > #{boundary}
     order by id desc limit #{size}"
)]
async fn select_latest_inner(
    rb: &dyn Executor, session_uuid: &Uuid, boundary: i64, size: u32,
) -> Vec<ChatMessageRecord> {}

pub async fn select_latest_by_session(
    rb: &dyn Executor, session_uuid: &Uuid, boundary: i64, size: u32,
) -> rbatis::Result<Vec<ChatMessageRecord>> {
    let mut v = Self::select_latest_inner(rb, session_uuid, boundary, size).await?;
    v.reverse();   // desc → asc
    Ok(v)
}

/// 窗口截断探测(§8.2): 游标之后是否存在窗口外的消息。
#[rbatis::py_sql(
    "select 1 from chat_message_record
     where session_uuid = #{session_uuid} and id > #{cursor} and \"timestamp\" <= #{boundary}
     limit 1"
)]
async fn exists_beyond_window_inner(
    rb: &dyn Executor, session_uuid: &Uuid, cursor: i64, boundary: i64,
) -> Vec<i32> {}

pub async fn exists_beyond_window(
    rb: &dyn Executor, session_uuid: &Uuid, cursor: i64, boundary: i64,
) -> rbatis::Result<bool> {
    Ok(!Self::exists_beyond_window_inner(rb, session_uuid, cursor, boundary).await?.is_empty())
}
```

## 6. service 与 controller

### 6.1 `service.rs` 追加 `sync_sessions`

```rust
pub async fn sync_sessions(
    rb: &RBatis,
    me: &str,
    dto: SyncRequestDTO,
) -> Result<SyncResponseVO, anyhow::Error> {
    let me_uuid: Uuid = me.parse()?;
    let boundary = window_boundary();
    let limit = dto.limit.unwrap_or(SYNC_DEFAULT_LIMIT).clamp(1, SYNC_MAX_LIMIT);
    let initial = dto.mode.as_deref() == Some("initial");

    // 1. 目标会话行
    let rows: Vec<UserSession> = match dto.sessions.as_deref() {
        None | Some([]) => UserSession::select_by_user(rb, &me_uuid).await?,
        Some(ids) => {
            // 指定会话: 逐个解析并查行(不存在/无权的跳过 —— UserSession 唯一键含 user_uuid,
            // 查询天然按 user 过滤, 无越权可能)
            let mut v = Vec::new();
            for id in ids {
                let Ok(u) = id.parse::<Uuid>() else {
                    warn!("[session/sync] 非法 session_uuid: {id}");
                    continue;
                };
                if let Some(row) = UserSession::select_by_user_and_session(rb, &me_uuid, &u).await? {
                    v.push(row);
                }
            }
            v
        }
    };

    // 2. 逐会话拉取(串行; 会话数 × 单分区索引扫, 开发期可接受, 性能注记见 §8)
    let mut sessions_out = Vec::new();
    for row in rows {
        let session_type = row.session_type.unwrap_or(0);
        let session_uuid = row.session_uuid;

        let (messages, has_more, cursor_for_truncated) = if initial {
            let msgs = if session_type == SESSION_TYPE_GROUP {
                GroupMessageRecord::select_latest_by_group(rb, &session_uuid, boundary, limit).await?
                    .into_iter().map(|m| group_msg_to_vo(m, &session_uuid)).collect::<Vec<_>>()
            } else {
                ChatMessageRecord::select_latest_by_session(rb, &session_uuid, boundary, limit).await?
                    .into_iter().map(|m| single_msg_to_vo(m, &session_uuid)).collect::<Vec<_>>()
            };
            (msgs, false, 0)   // initial: has_more 恒 false, 不探测截断
        } else {
            let cursor = row.synced_id.unwrap_or(0);
            let raw = if session_type == SESSION_TYPE_GROUP {
                GroupMessageRecord::select_sync(rb, &session_uuid, cursor, boundary, limit + 1).await?
            } else {
                ChatMessageRecord::select_sync(rb, &session_uuid, cursor, boundary, limit + 1).await?
            };
            let has_more = raw.len() > limit as usize;
            let mut msgs: Vec<SyncMessageVO> = raw.into_iter()
                .take(limit as usize)
                .map(|m| if session_type == SESSION_TYPE_GROUP {
                    group_msg_to_vo(m, &session_uuid)
                } else {
                    single_msg_to_vo(m, &session_uuid)
                })
                .collect();
            if msgs.is_empty() {
                continue;   // 增量模式: 无未同步消息的会话不输出(空响应=同步完毕)
            }
            if has_more {
                // 探测截断无意义(还有更多可拉), 但要先把多取的 1 条丢掉 —— take 已处理
            }
            let _ = &mut msgs;
            (msgs, has_more, cursor)
        };

        // 3. 截断探测: 仅 has_more=false 时(§2.3)
        let truncated = if has_more {
            false
        } else if initial {
            false
        } else {
            if session_type == SESSION_TYPE_GROUP {
                GroupMessageRecord::exists_beyond_window(rb, &session_uuid, cursor_for_truncated, boundary).await?
            } else {
                ChatMessageRecord::exists_beyond_window(rb, &session_uuid, cursor_for_truncated, boundary).await?
            }
        };

        let next_cursor = messages.last().map(|m| m.id).unwrap_or(0);
        sessions_out.push(SyncSessionVO {
            session_uuid: session_uuid.to_string(),
            session_type,
            messages,
            next_cursor,
            has_more,
            truncated_by_window: truncated,
        });
    }

    Ok(SyncResponseVO {
        server_time: chrono::Utc::now().timestamp_millis(),
        sessions: sessions_out,
    })
}
```

> **truncated 探测的 cursor**：增量模式用拉取前的 `synced_id`（探测"游标之后是否有窗口外的消息"）—— 写成 `cursor_for_truncated` 变量传入。VO 转换函数（`single_msg_to_vo` / `group_msg_to_vo`）为纯映射，字段对照 §2.2，此处从略（实现时按编译器补全即可）。

## 7. 三个不变量映射（验收标准，主方案 §8.5）

| 不变量 | 本接口的落实 |
|--------|-------------|
| **幂等** | 重复调用同参数：服务端游标未推进时重拉相同消息，客户端 `nano_id` 去重 —— 接口本身无状态副作用（除日志） |
| **单调** | 接口零写操作；游标推进只经 `/session/synced`（数据层只前进） |
| **完整** | `has_more` 循环 + 空响应终止：客户端可拉到 `synced_id` 推进点的全部窗口内消息；窗口外由 `truncated_by_window` 显式告知，**不静默** |

> 完整性上界仍是 at-most-once 落库（主方案 §6.4）—— 接口只承诺"库中存在的消息"不丢。

## 8. 性能注记（留任务 09）

- `sessions` 传空的筛选是**逐会话探测**（会话数 × 索引扫描 + limit+1 多取一条）。50 会话约 50 次单分区索引扫，毫秒级。数据量上来后若成为瓶颈：改为对 `user_session` 与消息表做一条 `EXISTS` 联查（或 Redis 维护"有未同步"标记）—— 优化项，不在本系列
- `select_sync` 命中 `idx_chat_msg_pull (session_uuid, id) INCLUDE ("timestamp")` —— 窗口过滤 index-only scan，免回表（任务 02 的索引在此兑现）

### 9.1 集成测试（`session_service` 相关，参照任务 04 的测试基建）

| 测试名 | 步骤与断言 |
|--------|-----------|
| `sync_returns_unsynced_only` | 造 2 个会话各 3 条消息，仅回报会话 A 的 `synced_id` → 响应只含 A 之外会话的消息；A 不出现 |
| `sync_orders_by_id_asc` | 同会话乱序插 3 条（timestamp 乱、id 递增）→ 响应按 id 升序 |
| `sync_has_more_and_batching` | 造 limit+1 条 → `has_more=true` 且恰好 limit 条；回报 `next_cursor` 后再拉 → 剩余 1 条 + `has_more=false` |
| `sync_7day_window_filters` | 插 8 天前 1 条 + 今天 2 条 → 只回今天 2 条且 `truncated_by_window=true`；游标回报后窗口外消息不再出现 |
| `sync_no_truncated_when_all_recent` | 全部消息在窗口内 → `truncated_by_window=false` |
| `sync_initial_mode` | 新用户（`user_session` 行 synced=0）`mode=initial` → 每会话最新 limit 条、`has_more=false` |
| `sync_empty_sessions_terminates` | 全部同步完成后 → `sessions` 为空数组 |
| `sync_limit_clamped` | `limit=99999` → 实际返回 ≤ 200 |
| `sync_specified_sessions_only` | `sessions` 指定 1 个 → 只返回该会话；不存在的 uuid 被跳过不报错 |

### 13.2 缺陷 T（本任务发现并修复）：`UserSession::upsert` 的 `COALESCE` 类型推断 + 语句缓存

`UserSession::upsert` 的 `COALESCE($5, 0)` / `COALESCE($6, 0)` 会让 PG 把 `$5`/`$6` 推断为 **int4**；当某连接先用「`synced_id=None`（NULL）」预编译该语句（如桥接 `add_user_chat_read` 传 None）并进入 rbdc-pg 语句缓存后，同连接后续传 **int8** 值复用该缓存语句时，8 字节绑定对 int4 参数 → `22P03: 在绑定参数中出现不正确的二进制数据`（集成测试 §9.1 两次 upsert 直接暴露：第一次成功、第二次失败）。

**修复**：`COALESCE($5::bigint, 0)` / `COALESCE($6::bigint, 0)` 显式固化 int8，消除推断歧义。该缺陷会影响所有「同一连接上对 `user_session` 的重复写入」（`/session/read`、`/session/synced`、桥接多条上报等）。

### 13.3 `rbdc::Uuid::from_str` 不校验

`rbdc::Uuid` 是 `struct Uuid(String)`，其 `FromStr` 永远成功（仅包装字符串），非法 `session_uuid` 会穿透到绑定层报错（§9.9 暴露）。**修复**：`sync_sessions` 指定会话分支用 `uuid::Uuid::parse_str` 校验后再转 `rbdc::Uuid`，非法值记 warn 跳过。
