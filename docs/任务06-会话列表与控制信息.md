## 2. 修正任务 03 的一个判断（preview）

任务 03 §3.4 认为 `raw` 是 bincode 协议体、preview 生成需要解协议、只能留 NULL。**核实后此判断过虑**：

- `TextQuicMsg.raw: Vec<u8>` 是**纯消息内容**（`common/src/utils/text_msg.rs:44`）
- bincode 帧序列化只发生在**传输层**（`HeadMsg + TextQuicMsg` 整体 get_bytes）；落库只存 `raw` 字段本身
- 客户端对它直接 `String::from_utf8(raw)`（`TextQuicMsgVo::from`）—— 即文本消息的 UTF-8 字节

**结论**：preview 在 entity 聚合层生成，一行代码：

```rust
String::from_utf8_lossy(&raw).chars().take(256).collect::<String>()
```

> `chars().take()` 保证 UTF-8 安全截断（不切半个多字节字符）。非文本消息（图片等）截断同样无害 —— 客户端按 `text_type` 显示"[图片]"类标签时不用 preview。

**改动**：`aggregate_user_sessions`（任务 03）里 `update_last_message(..., None)` 的两处调用改为传入生成值；单聊用 `msg.raw`，群聊用 `latest_msg.raw`。

### 3.2 `Session` 追加列表查询

`session.rs` 新增专用行结构 + py_sql（主方案 §9.1 的完整 SQL，keyset 化）：

```rust
/// 会话列表行(entity 层形态, http_service 转 VO)。
#[derive(Clone, Deserialize, Serialize, Debug)]
pub struct SessionListRow {
    pub session_uuid: Uuid,
    pub session_type: Option<i16>,
    pub peer_uuid: Option<Uuid>,
    pub last_message_id: Option<i64>,
    pub last_message_at: Option<i64>,
    pub last_preview: Option<String>,
    pub pinned: Option<i16>,
    pub muted: Option<i16>,
    pub unread: Option<i64>,
}
```

```rust
impl Session {
    /// 会话列表(§9.1): 未读现算 + 软删复活 + keyset 分页。
    /// cursor 三元组为 None(首页)时跳过分页条件。
    ///
    /// 已知局限(主方案 §4.3 注): 排序键在 join 的 session 表上, 索引只帮过滤不帮排序,
    /// 实际为该用户会话行的内存排序 —— 单用户几百会话可接受, 列入任务 09 实测项。
    #[rbatis::py_sql(
        "select s.session_uuid, s.session_type, s.peer_uuid, \
         c.last_message_id, c.last_message_at, c.last_preview, s.pinned, s.muted, \
         (case s.session_type \
            when 1 then (select count(*) from chat_message_record m \
                         where m.session_uuid = s.session_uuid and m.id > s.last_read_id \
                           and m.recv_user = #{me}) \
            else (select count(*) from group_message_record m \
                  where m.group_uuid = s.session_uuid and m.id > s.last_read_id \
                    and m.send_user <> #{me}) \
          end) as unread \
         from user_session s \
         join session c on c.session_uuid = s.session_uuid \
         where s.user_uuid = #{me} \
           and (s.deleted_at is null or c.last_message_at > s.deleted_at) \
           and (#{cur_pinned} is null or (s.pinned, coalesce(c.last_message_at, 0), s.session_uuid) \
                < (#{cur_pinned}, #{cur_at}, #{cur_uuid})) \
         order by s.pinned desc, c.last_message_at desc nulls last, s.session_uuid \
         limit #{size}"
    )]
    async fn select_list_inner(
        rb: &dyn Executor,
        me: &Uuid,
        cur_pinned: Option<i16>,
        cur_at: Option<i64>,
        cur_uuid: Option<Uuid>,
        size: u32,
    ) -> Vec<SessionListRow> {}

    pub async fn select_list(
        rb: &dyn Executor,
        me: &Uuid,
        cursor: Option<(i16, i64, Uuid)>,
        size: u32,
    ) -> rbatis::Result<Vec<SessionListRow>> {
        let (p, a, u) = cursor.map(|(p, a, u)| (Some(p), Some(a), Some(u)))
            .unwrap_or((None, None, None));
        Ok(Self::select_list_inner(rb, me, p, a, u, size).await?)
    }
}
```

> **keyset 的 null 处理**：`last_message_at` 可为 NULL（无消息会话）—— 排序用 `nulls last`（空会话沉底），比较用 `coalesce(c.last_message_at, 0)`（三元组行比较不认 null）。首页条件 `#{cur_pinned} is null` 直接短路。
>
> **CASE 的 `else` 分支**只对 `session_type = 2` 成立（主方案 §9.1 注）—— 3/4 接入时必须补分支，模型注释已标。

### 4.2 service（`service.rs` 追加）

```rust
const SESSION_LIST_DEFAULT_SIZE: u32 = 50;
const SESSION_LIST_MAX_SIZE: u32 = 100;

pub async fn list_sessions(
    rb: &RBatis,
    me: &str,
    dto: SessionListDTO,
) -> Result<SessionListResponseVO, anyhow::Error> {
    let me_uuid: Uuid = me.parse()?;
    let size = dto.size.unwrap_or(SESSION_LIST_DEFAULT_SIZE)
        .clamp(1, SESSION_LIST_MAX_SIZE);

    // 解析游标(首页为 None)
    let cursor = match dto.cursor {
        Some(c) => Some((c.pinned, c.last_message_at,
                         c.session_uuid.parse().map_err(|_| anyhow!("游标 session_uuid 非法"))?)),
        None => None,
    };

    // size+1 探测 has_more(与 /session/sync 同款手法)
    let mut rows = Session::select_list(rb, &me_uuid, cursor, size + 1).await?;
    let has_more = rows.len() > size as usize;
    rows.truncate(size as usize);

    let sessions: Vec<SessionVO> = rows.into_iter().map(|r| SessionVO {
        session_uuid: r.session_uuid.to_string(),
        session_type: r.session_type.unwrap_or(0),
        peer_uuid: r.peer_uuid.map(|p| p.to_string()),
        last_message_id: r.last_message_id.unwrap_or(0),
        last_message_at: r.last_message_at.unwrap_or(0),
        last_preview: r.last_preview.unwrap_or_default(),
        pinned: r.pinned.unwrap_or(0),
        muted: r.muted.unwrap_or(0),
        unread: r.unread.unwrap_or(0),
    }).collect();

    // next_cursor = 本页最后一行(客户端回传原样三元组)
    let next_cursor = if has_more {
        sessions.last().map(|s| SessionListCursor {
            pinned: s.pinned,
            last_message_at: s.last_message_at,
            session_uuid: s.session_uuid.clone(),
        })
    } else { None };

    Ok(SessionListResponseVO { sessions, has_more, next_cursor })
}
```

控制信息三接口 service（同一模式，给出 pin 的完整样例，mute/delete 同构）：

```rust
/// 置顶/取消置顶。
/// 先聚合(§6.1 触发表: 控制信息变更顺带聚合, 保证 session/user_session 行存在),
/// 再更新 —— update 影响 0 行时返回"会话不存在"业务错误。
pub async fn pin_session(
    rb: &RBatis,
    me: &str,
    dto: SessionControlDTO,
) -> Result<(), anyhow::Error> {
    let me_uuid: Uuid = me.parse()?;
    let s: Uuid = dto.session_uuid.parse()?;
    let _ = aggregate_user_sessions(rb, &me_uuid).await;   // 幂等, 失败不阻塞
    let affected = UserSession::update_pinned(
        rb, &me_uuid, &s, dto.value.unwrap_or(1),
    ).await?;
    if affected == 0 {
        return Err(anyhow!("会话不存在: {}", dto.session_uuid));
    }
    Ok(())
}
```

> `delete_session` 调 `UserSession::soft_delete`（任务 03 已实现，含推到底）；`mute_session` 调 `update_muted`。两者同样「先聚合再更新」。

## 9. 实施记录（实施后补记）

任务 06 已实施完成。与任务书原文的差异与验证结果如下。

### 9.1 keyset 游标参数必须显式转型（缺陷 T 同源）

`Session::select_list` 的三个游标参数为 `Option`：首页传 NULL（类型 UNKNOWN），后续页传具体值。同连接复用 rbdc-pg 语句缓存时，后者的具体类型与缓存中的推断类型不符会 `22P03`（任务 05 §13.2 缺陷 T 同源）。

**落地**：SQL 中写 `#{cur_pinned}::int2`、`#{cur_at}::int8`、`#{cur_uuid}::uuid` 显式固化类型。

### 9.2 keyset 第三排序键改为 `session_uuid desc`

任务书 §3.2 的 `order by ... , s.session_uuid`（升序）与三元组行比较 `(pinned, at, uuid) < (...)` 方向不一致：当两个会话 `last_message_at` 相同（毫秒级撞车可能）时会漏行。**改为 `s.session_uuid desc`**，使三个排序键同为降序，行比较 `<` 语义正确（`list_keyset_no_gap_no_dup` 用例守护）。

### 9.3 `UserSession::upsert` 不写 `pinned` / `muted`

`UserSession::upsert`（任务 03）是**懒创建**语义，只插 8 列（游标 + 类型 + peer），`pinned`/`muted` 走 DDL 默认 0。控制字段只能经 `update_pinned` / `update_muted` 写入（控制接口正是如此）。测试助手 `upsert_user_session_ex` 据此在 upsert 后按需补调控制方法。

### 9.4 其他差异

1. **`me` 参数类型**：`list_sessions` / `pin_session` / `mute_session` / `delete_session` 统一用 `Option<String>`（与 `session_service` 既有惯例一致），原文 §4.2 写 `&str`。
2. **非法 `session_uuid` 校验**：`list_sessions` 游标与 `prepare_control` 均用 `uuid::Uuid::parse_str` 校验（`rbdc::Uuid::from_str` 不校验，任务 05 §13.3 同源），非法值直接返回业务错误。
3. **控制接口先聚合后更新**：`prepare_control` 内 `aggregate_user_sessions`（幂等，失败不阻塞）后再 update；影响 0 行返回「会话不存在」。
4. preview 生成与任务书 §2 一致：`String::from_utf8_lossy(raw).chars().take(256)`，接入 `aggregate_user_sessions` 两处 `update_last_message`。
