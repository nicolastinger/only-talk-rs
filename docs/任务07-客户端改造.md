### 3.1 新增 `src-tauri/src/utils/session_uuid.rs`

```rust
//! 会话标识派生(服务端 common::utils::session_uuid 的逐行复刻)。
//! ⚠️ 算法与 CONV_NAMESPACE 必须与服务端严格一致 —— 由 testdata 向量断言守护。

use uuid::Uuid;

/// 与服务端 config_str::CONV_NAMESPACE_STR 同值(从向量文件核对)。
pub const CONV_NAMESPACE_STR: &str = "<服务端任务01生成的值>";

/// 单聊会话标识: 字节序规范化 + v5 派生, 双向对称。
pub fn single_session_uuid(a: &Uuid, b: &Uuid) -> Uuid {
    let (lo, hi) = if a.as_bytes() <= b.as_bytes() { (a, b) } else { (b, a) };
    Uuid::new_v5(&namespace(), format!("{lo}:{hi}").as_bytes())
}

fn namespace() -> Uuid {
    Uuid::parse_str(CONV_NAMESPACE_STR).expect("CONV_NAMESPACE_STR 非法")
}
```

注册进模块树（`utils/mod.rs`）。可选：包一层 `#[tauri::command] pub fn session_uuid_cmd(a: String, b: String) -> Result<String, String>` 暴露给前端做会话 key —— 建议提供。

### 5.1 已读低估自愈（先讲清语义，这是本任务最关键的决策）

新契约报 `last_read_id`（服务端消息 id），但在线消息本地无 id。设计：

- 客户端报「该会话本地 **max(server_id)**」—— 只统计已同步落库的消息
- 在线读了未同步（无 id）的消息 → 本次上报**跳过或低估**
- **低估无害**：服务端 `last_read_id` 偏小 → 服务端未读数偏大，但**客户端角标是本地算的**（`is_new && is_received`），界面无感知
- **自愈**：下次同步把 `server_id` 带入 → 下次上报推进到位
- **宁少勿过**：反过来「报过头」会把还没同步下来的消息标已读、丢角标 —— 本设计从机制上杜绝

### 5.3 `sync_sessions_offline`（核心循环）

```rust
/// /session/sync 空响应终止循环(主方案 §8.3 / 任务05 §2.3 协议)。
async fn sync_sessions_offline() -> Result<(), anyhow::Error> {
    let me = get_user_info("uuid").await?;

    // 首次判定: 本地存在任何 synced_id > 0 的会话 → 增量; 否则 initial
    let mode = if has_any_synced_session(&me).await? { "incremental" } else { "initial" };

    loop {
        let body = serde_json::json!({ "mode": mode, "sessions": [], "limit": 100 });
        let resp = post_request(format!("{}/session/sync", TALK_API), body.to_string()).await?;
        let result: HttpResult = parse_http_result(&resp.body)?;
        if result.code != 200 || result.data.is_null() {
            break;
        }
        let sync: SyncResponse = serde_json::from_value(result.data)?;
        if sync.sessions.is_empty() {
            break;   // 终止条件(§2.3): 无未同步会话
        }

        let mut acks: Vec<serde_json::Value> = Vec::new();
        for s in &sync.sessions {
            for msg in &s.messages {
                if s.session_type == 1 {
                    insert_single_sync_message(msg).await?;      // §5.4
                } else {
                    insert_group_sync_message(msg).await?;       // §5.4
                }
            }
            // 本地会话行: session_uuid + synced_id 落库
            update_local_session_cursor(&me, &s.session_uuid, s.next_cursor).await?;
            acks.push(serde_json::json!({
                "session_uuid": s.session_uuid,
                "synced_id": s.next_cursor,
            }));
        }

        // 先落库再回报(宁重勿漏; 回报失败 → 下轮重拉, nano_id 去重兜住)
        post_request(
            format!("{}/session/synced", TALK_API),
            serde_json::to_string(&serde_json::json!({ "sessions": acks }))?,
        ).await?;
    }
    Ok(())
}
```

> `has_more=true` 的会话**无需特殊处理**：回报 `synced_id` 后，下轮服务端筛选「有未同步」自动包含它（`id > synced_id` 仍成立）—— 循环天然继续。`has_more` 仅用于 UI 进度提示。

### 5.4 消息分流落库

```rust
/// 单聊: SyncMessageVO → TextQuicMsgVo → 复用现有 insert_chat_record 去重链
async fn insert_single_sync_message(msg: &SyncMessage) -> Result<(), anyhow::Error> {
    let vo = TextQuicMsgVo {
        nano_id: msg.nano_id.clone(),
        text_type: msg.text_type,
        raw: String::from_utf8_lossy(&msg.raw).to_string(),
        recv_user: msg.recv_user.clone(),
        send_user: msg.send_user.clone(),
        timestamp: msg.timestamp,
    };
    // is_new: 本地已有同 nano_id → false(不计角标, §现有逻辑)
    let is_new = insert_chat_record(&vo).await?;
    if is_new && msg.recv_user == get_user_info("uuid").await? {
        bump_local_unread(&msg.send_user, &vo).await?;   // 沿用现有角标累加模式
    }
    // server_id 记录(已读上报用): UPDATE chat_record SET server_id WHERE nano_id = ?
    set_server_id(&msg.nano_id, msg.id).await?;
    Ok(())
}

/// 群聊: recv_user 即 group_uuid, text_type 即 msg_type(任务05 §2.3 契约)
async fn insert_group_sync_message(msg: &SyncMessage) -> Result<(), anyhow::Error> {
    let record = GroupChatRecord {
        id: 0,
        nano_id: msg.nano_id.clone(),
        text_type: msg.text_type,
        raw: String::from_utf8_lossy(&msg.raw).to_string(),
        group_id: msg.recv_user.clone(),        // 群标识在 recv_user
        send_user: msg.send_user.clone(),
        timestamp: msg.timestamp,
    };
    let is_new = GroupChatRecord::insert(&record).await?;   // 现有去重
    if is_new && msg.send_user != get_user_info("uuid").await? {
        bump_local_group_unread(&msg.recv_user, &record).await?;
    }
    set_group_server_id(&msg.nano_id, msg.id).await?;
    Ok(())
}
```

## 7. TS 类型（`packages/types/src/`）

供前端同事消费（结构与任务 04–06 的服务端 VO 逐字段对齐）：

```typescript
// packages/types/src/session.ts
export interface SessionListItem {
  session_uuid: string;
  session_type: 1 | 2;
  peer_uuid: string | null;      // 单聊: 对方; 群聊: null(用 session_uuid 查群资料)
  last_message_id: number;
  last_message_at: number;
  last_preview: string;
  pinned: number;                // 0 | 1
  muted: number;                 // 0 | 1
  unread: number;
}

export interface SessionListResponse {
  sessions: SessionListItem[];
  has_more: boolean;
  next_cursor: { pinned: number; last_message_at: number; session_uuid: string } | null;
}

export interface SyncMessage {
  id: number;
  nano_id: string;
  session_uuid: string;
  session_type: 1 | 2;
  send_user: string;
  recv_user: string;             // 群聊时即 group_uuid
  text_type: number;             // 单聊/群聊值域不同, 按 session_type 解释
  timestamp: number;
  raw: number[];
}
```

> `raw: number[]` 与现有接口一致；前端做 `String.fromCharCode`/UTF-8 解码的既有逻辑可复用。

前端实施要点（交前端同事）：`quic_sync_complete` 事件后触发列表刷新；会话组件以 `session_uuid` 为 React key（替代现在复用 `send_user` 的做法）；pin/mute/delete 按钮接三个 POST。
