# 任务 13：移动端通知中心后端优化

> 来源：2026-09-23 讨论定稿（移动端通知中心接入需求）
> 状态：已实施
> 定位：把「通知只存不查、只推单端、字段只写不用」的通知域，补齐为移动端通知中心所需的**列表分页 / 未读汇总 / 分类过滤 / 同源聚合 / 双端实时推送**完整能力。

---

## 1. 目标与边界

### 1.1 本任务做什么

| # | 内容 | 侧 |
|---|------|-----|
| 1 | `/notify/list`：keyset 分页 + `is_read`/`level1`/`level2` 过滤，返回列表、下一页游标、未读总数 | 服务端 |
| 2 | `/notify/unread_summary`：未读总数 + 按 `(level1, level2)` 分组（角标 + 分类 tab） | 服务端 |
| 3 | `/notify/mark_read`：指定 id 批量已读（兼容原协议）；`ids` 为空时按分类全部已读 | 服务端 |
| 4 | 索引优化：`(user_id, is_read, created_at desc, id desc)` 复合索引 + `(user_id, created_at desc, id desc)`，删除低选择性 `is_read` 单列索引 | DDL |
| 5 | 推送链路统一：删除 `group_service` 内私有副本与 `api::user_integrated_service` 内联重复，统一走 `system_notification::push_notification_via_quic` | 服务端 |
| 6 | 双端实时推送：通知推送同时下发 PC 与 MOBILE（修复仅 PC 端在线的历史缺陷） | 服务端 |
| 7 | 推送非致命化：推送失败只告警，不再让「加好友/处理好友」等主流程整体失败 | 服务端 |
| 8 | 同源聚合落地：`unread_count`/`biz_id`/`level1-3` 语义落地 —— 点赞/心动/评论类通知同源未读合并计数，而非每条新行 | 服务端 |
| 9 | 清理遗留死接口/文档同步 | 文档 |

### 1.2 本任务不做什么

| 不做 | 理由 |
|------|------|
| 改动 `/notify/get_user_unread_notification` 协议 | 旧客户端仍在使用，保留兼容（仅返回窗口内未读） |
| 跨节点路由改造 | 任务范围外，见 `集群路由方案.md` §偏差记录（未实现跨节点转发） |
| 客户端 SQLite 表结构调整 | 服务端字段与客户端表字段已对齐，仅需文档确认 |

## 2. 改动清单

### 2.1 接口层（`/notify`）

| 接口 | 方法 | 入参 | 出参 |
|------|------|------|------|
| `/notify/get_user_unread_notification` | POST | - | `Vec<SystemNotification>`（保留，兼容旧客户端） |
| `/notify/list` | POST | `{cursor?, size?, is_read?, level1?, level2?}` | `{notifications[], has_more, next_cursor?, unread_total}` |
| `/notify/unread_summary` | POST | - | `{total, groups[{level1,level2,count}]}` |
| `/notify/mark_read` | POST | `{ids[]?, level1?, level2?}` | 204（`ids` 为空 → 按分类全部已读） |

- 列表排序键 `(created_at desc, id desc)`，游标为 `{created_at, id}`；客户端原样回传 `next_cursor`。
- `size` clamp `[1, 100]`，默认 50；`limit+1` 探测 `has_more`。

### 2.2 索引（`system_notification.sql`）

```sql
CREATE INDEX IF NOT EXISTS idx_system_notification_user_read_created
    ON public.system_notification USING btree (user_id, is_read, created_at DESC, id DESC);
CREATE INDEX IF NOT EXISTS idx_system_notification_user_created
    ON public.system_notification USING btree (user_id, created_at DESC, id DESC);
DROP INDEX IF EXISTS idx_system_notification_is_read;
DROP INDEX IF EXISTS idx_system_notification_user_id_created_at;
```

- `is_read` 单列选择性极低，无查询价值，删除。
- 旧 `(user_id, created_at)` 升序索引被 `(user_id, created_at desc, id desc)` 覆盖，删除。

### 2.3 推送链路

- **统一入口**：所有通知推送只走 `system_notification::push_notification_via_quic`。
  - 删除 `group_service.rs` 内的私有副本。
  - `api::user_integrated_service.rs` 的 `add_user_with_notify` / `process_friend_with_notify` 改为调用统一入口。
- **双端下发**：对 `[PC, MOBILE]` 各发一次内部 QUIC 请求（`send_msg_to_user` 同源），修复此前只推 PC 端、移动端在线收不到通知的问题。
- **非致命化**：单端失败仅 `warn!`；全部失败返回错误供调用方记录，但不再 `?` 上抛打断主流程。

### 2.4 同源聚合

`SystemNotification::upsert_unread_aggregate`：

- 聚合键：`(user_id, level1, level2, level3, biz_id)`，仅匹配**未读**（`is_read=false`）且窗口内。
- 命中 → `unread_count + 1` 并刷新 `content`/`created_at`，返回更新后的旧行。
- 未命中 → 插入新行。
- 应用于：广场心动/互相心动、动态点赞/评论（`aggregate: true`）。
- 好友请求/处理、群邀请/结果保持每次独立（`aggregate: false`，`biz_id` 为唯一业务键，天然不聚合）。

### 2.5 层级常量（`config_str.rs`）

| 常量 | 值 | 含义 |
|------|-----|------|
| `NOTIFY_LEVEL1_SYSTEM` | 1 | 功能大类：系统通知 |
| `NOTIFY_LEVEL2_FRIEND/GROUP/PLAZA/MOMENT` | 1/3/4/5 | 子模块 |
| `NOTIFY_LEVEL3_FRIEND_REQUEST/…` | 1/2/… | 具体功能组 |
