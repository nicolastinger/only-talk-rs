# 动态广场（Moments）设计方案

> 本文档描述动态广场功能的**后端**实现：数据模型、实体、REST 接口（统一 POST）、业务规则、数据访问与客户端对接。
> 涉及仓库：`only-talk-rs`（后端），前端交互见 `only-talk-app` 相关实现。

> **✅ 落地状态（2026-08）**：数据表 + rbatis 实体模型 + http_service 接口已实现，接口统一采用 **POST** 风格（弃用 RESTful 动词）。

## 1. 目标

为客户端提供「动态广场」图文社区能力：

- 发布图文动态（最多 9 图），支持「公开 / 仅自己」可见性
- 广场按三种流分页浏览：`plaza`（全部公开）、`following`（我关注的人公开）、`mine`（我的）
- 点赞 / 取消点赞（软删切换）、查看「赞过的人」列表
- 发表评论、分页查看评论
- 关注 / 取消关注作者
- 点击动态进入详情页：大图浏览 + 页内评论 + 赞过的人

## 2. 背景与现状

- 作者资料（`basic_user.username/icon`）**不做冗余快照**，一律通过 `JOIN basic_user` 动态获取。
- 图片不内嵌在业务表中：动态的 `uuid` 同时作为 `biz_record` / `biz_file_link` 的 `biz_id`（`biz_type='moment'`），图片 URL 由客户端通过 `getFiles(momentUuid)` 单独解析。
- 点赞数 / 评论数**实时计算**（`COUNT(*)` 相关子查询），不缓存（未引入 Redis 计数）。
- 关注关系独立成表（动态广场专用），与好友/黑名单等逻辑解耦。

## 3. 数据模型（PostgreSQL）

### 3.1 `moment`（动态主体）

```sql
CREATE TABLE IF NOT EXISTS moment (
    uuid uuid NOT NULL,                  -- 动态主键(同时也是图片分组 biz_id)
    author_uuid uuid NOT NULL,           -- 作者
    content text NOT NULL,               -- 文案内容
    visibility int2 DEFAULT 0 NOT NULL,  -- 可见性: 0-公开, 1-仅自己
    is_del bool DEFAULT false NOT NULL,  -- 是否删除
    created_at int8 NOT NULL,            -- 创建时间
    updated_at int8 NOT NULL,            -- 更新时间
    CONSTRAINT moment_pk PRIMARY KEY (uuid)
);
CREATE INDEX IF NOT EXISTS idx_moment_visibility_created ON public.moment USING btree (visibility, created_at DESC);
CREATE INDEX IF NOT EXISTS idx_moment_author ON public.moment USING btree (author_uuid);
```

> `(visibility, created_at DESC)` 支撑广场流「按公开 + 时间倒序」；`(author_uuid)` 支撑「我的 / 某用户动态」。

### 3.2 `moment_comment`（评论，扁平无回复）

```sql
CREATE TABLE IF NOT EXISTS moment_comment (
    id uuid NOT NULL,                    -- 主键
    moment_uuid uuid NOT NULL,           -- 动态key
    author_uuid uuid NOT NULL,           -- 评论作者
    content text NOT NULL,               -- 评论内容
    is_del bool DEFAULT false NOT NULL,  -- 是否删除
    created_at int8 NOT NULL,            -- 创建时间
    CONSTRAINT moment_comment_pk PRIMARY KEY (id)
);
CREATE INDEX IF NOT EXISTS idx_moment_comment_moment ON public.moment_comment USING btree (moment_uuid, created_at);
```

> 当前为**扁平评论**，无 `reply_to`/`parent_id`，不支持回复楼；后续如需楼中楼再扩列。

### 3.3 `moment_like`（点赞，UNIQUE 约束保证一人一赞）

```sql
CREATE TABLE IF NOT EXISTS moment_like (
    id uuid NOT NULL,                    -- 主键
    moment_uuid uuid NOT NULL,           -- 动态key
    user_uuid uuid NOT NULL,             -- 点赞用户
    is_del bool DEFAULT false NOT NULL,  -- 是否删除(取消点赞=软删)
    created_at int8 NOT NULL,            -- 创建时间
    CONSTRAINT moment_like_pk PRIMARY KEY (id),
    CONSTRAINT moment_like_unique UNIQUE (moment_uuid, user_uuid)
);
CREATE INDEX IF NOT EXISTS idx_moment_like_moment ON public.moment_like USING btree (moment_uuid);
CREATE INDEX IF NOT EXISTS idx_moment_like_user  ON public.moment_like USING btree (user_uuid);
```

> 因有 `UNIQUE(moment_uuid, user_uuid)`，取消点赞只翻转 `is_del`（软删），不新增行。

### 3.4 `user_follow`（关注）

```sql
CREATE TABLE IF NOT EXISTS user_follow (
    id uuid NOT NULL,                    -- 主键
    follow_user_uuid uuid NOT NULL,      -- 关注者uuid
    target_user_uuid uuid NOT NULL,      -- 被关注者uuid
    is_del bool DEFAULT false NOT NULL,  -- 是否删除(取消关注=软删)
    created_at int8 NOT NULL,            -- 创建时间
    CONSTRAINT user_follow_pk PRIMARY KEY (id),
    CONSTRAINT user_follow_unique UNIQUE (follow_user_uuid, target_user_uuid)
);
CREATE INDEX IF NOT EXISTS idx_user_follow_follow ON public.user_follow USING btree (follow_user_uuid);
CREATE INDEX IF NOT EXISTS idx_user_follow_target ON public.user_follow USING btree (target_user_uuid);
```

## 5. API 设计（全部 POST）

模块：`crates/http_service/src/http_service/moment_service/`，注册于 `http_service/mod.rs`：

```
.service(web::scope("/moment").configure(init_moment_service))
```

| 方法 | 路径 | 说明 | 请求体 | 返回 |
|---|---|---|---|---|
| POST | `/moment/create` | 发布动态 | `CreateMomentDTO` | `MomentVO` |
| POST | `/moment/list` | 分页动态流（feed） | `ReqList<MomentListQuery>` | `MomentListVO` |
| POST | `/moment/detail/{moment_uuid}` | 单条详情 | 空（路径参数） | `MomentVO` |
| POST | `/moment/delete` | 删除动态（仅作者，软删） | `DeleteMomentDTO` | `bool` |
| POST | `/moment/like/switch` | 点赞/取消点赞切换 | `LikeToggleDTO` | `bool` |
| POST | `/moment/like/list` | 赞过的人分页 | `ReqList<LikeListQuery>` | `MomentLikerListVO` |
| POST | `/moment/comment` | 发表评论 | `AddCommentDTO` | `MomentCommentVO` |
| POST | `/moment/comment/list` | 评论分页 | `ReqList<CommentListQuery>` | `MomentCommentListVO` |
| POST | `/moment/follow/switch` | 关注/取消关注切换 | `FollowToggleDTO` | `bool` |

所有接口从 JWT 取当前用户 `uuid`（`get_uuid_from_header!`）。读接口校验可见性，写接口仅能操作自己。

## 6. 业务规则

1. **发布时间**：`uuid = Uuid::now_v7()`；`content` 先 `trim`，空则报错，非空截断到 2000 字符；`file_ids` 最多 9 张。
2. **可见性**：`visibility` 归一化为 `0/1`；`1-仅自己` 仅作者本人可读，他人访问返回「无权访问该动态」。
3. **图片关联**（`/moment/create` 事务内）：先插 `moment` 行，再插 `biz_record`（`biz_type='moment'`, `biz_id=moment_uuid`），随后逐张 `file_ids` 插 `biz_file_link`（`biz_id=moment_uuid`, `file_id` 转 `Uuid`）。事务失败整体回滚。
4. **点赞切换**：按 `(moment_uuid, user_uuid)` 查找；存在则翻转 `is_del`（软删），不存在则插入；配合 `UNIQUE` 保证一人一条记录。
5. **关注切换**：按 `(follow_user_uuid, target_user_uuid)` 类似逻辑；**不能关注自己**；也复用软删。
6. **评论**：`trim`、空则报错、截断到 1000 字符；先 `ensure_moment_visible`，插入后经 `get_comment_vo`（`JOIN basic_user`）返回完整 VO。
7. **可见性校验**（`ensure_moment_visible`）：行存在且 `is_del=false`；若 `visibility==1` 且 `author_uuid != me`，报「无权访问该动态」；行不存在报「动态不存在」。
8. **时间戳**：统一 Unix 秒（`common::utils::time::get_now_time_stamp_as_secs`）。
9. **删除动态**（`/moment/delete`）：**仅作者**可删；按 `moment_uuid` 载入行，非本人报「无权操作」，已软删则幂等返回成功；置 `is_del=true` 并刷新 `updated_at`。因所有 feed / 详情 / 赞过 / 评论查询都已过滤 `is_del=false`，软删后动态即刻从各处消失，无需额外清理关联数据（图片/点赞/评论成为无害孤儿）。

## 7. Feed 筛选（`build_moment_filter`）

`feed` ∈ `{ plaza, following, mine }`；`None` 保持兼容旧逻辑（公开 + 自己）。可叠加 `author_uuid` 过滤（如 TA 的动态页）：

| feed | WHERE 片段 |
|---|---|
| `mine` | `m.author_uuid = me` |
| `following` | `m.visibility = 0 AND m.author_uuid IN (SELECT target_user_uuid FROM user_follow WHERE follow_user_uuid = me AND is_del = false)` |
| `plaza` | `m.visibility = 0` |
| `None` | `m.visibility = 0 OR m.author_uuid = me` |

外层必带 `m.is_del = false AND (...)`；若传 `author_uuid` 再追加 `AND m.author_uuid = ?`。

## 8. 数据访问要点

- `/moment/list`：一次 `JOIN basic_user` 分页查询 + `COUNT(*)` 求 total；图片/点赞/评论数用**相关子查询**实时计算，`liked_by_me` / `followed_by_me` 各一条子查询。
  ```sql
  SELECT m.uuid, m.author_uuid, m.content, m.visibility::int AS visibility,
         m.created_at, m.updated_at, bu.username, bu.icon,
         (SELECT count(*) FROM biz_file_link bf WHERE bf.biz_id = m.uuid) AS image_count,
         (SELECT count(*) FROM moment_like ml WHERE ml.moment_uuid = m.uuid AND ml.is_del = false) AS like_count,
         (SELECT count(*) FROM moment_comment mc WHERE mc.moment_uuid = m.uuid AND mc.is_del = false) AS comment_count,
         (SELECT count(*) FROM moment_like ml2 WHERE ml2.moment_uuid = m.uuid AND ml2.user_uuid = ? AND ml2.is_del = false) AS liked_by_me,
         (SELECT count(*) FROM user_follow uf WHERE uf.follow_user_uuid = ? AND uf.target_user_uuid = m.author_uuid AND uf.is_del = false) AS followed_by_me
  FROM moment m JOIN basic_user bu ON m.author_uuid = bu.uuid
  WHERE <建好的 WHERE> ORDER BY m.created_at DESC LIMIT ? OFFSET ?
  ```
- `/moment/detail/{uuid}`：同上查询结构，`WHERE m.uuid = ? AND m.is_del = false AND (m.visibility = 0 OR m.author_uuid = ?)`，无行报「动态不存在」。
- `/moment/comment/list`：`JOIN basic_user`，`WHERE c.moment_uuid = ? AND c.is_del = false ORDER BY c.created_at DESC LIMIT/OFFSET` + `COUNT(*)`。
- `/moment/like/list`：`JOIN basic_user`，`WHERE ml.moment_uuid = ? AND ml.is_del = false ORDER BY ml.created_at DESC LIMIT/OFFSET` + `COUNT(*)`。
- 分页约定：`page_num.max(1)`，`page_size.clamp(1, 50)`（controller 默认 20），`offset = (page_num-1)*page_size`。

## 9. 返回风格

- 读接口 / 带数据写接口：service 返回 `Result<String, anyhow::Error>`，用 `CommonResponseRef::success_json(&vo)`（`code: 200`）；controller 用 `respond_json_any!`。
- 布尔切换（like/follow）：controller 分支，`Ok(_) => succeed()`（`CommonResponse::<bool>::success(true)`），`Err(t) => fail(&t)`（400 + `CommonResponseNoDataRef::error_json(&e.to_string())`）。

## 10. 客户端对接（only-talk-app）

- `packages/services/src/momentService/`：`get_moment_list`、`get_moment_detail`、`create_moment`、`delete_moment`、`switch_moment_like`、`switch_user_follow`、`post_moment_comment`、`get_moment_comments`、`get_moment_likers`，统一经 `parseData`（`code === 200`）。
- `packages/types/src/moment/`：`MomentVo`、`MomentListResult`、`MomentCommentVo`、`MomentCommentListResult`、`MomentLikerVo`、`MomentLikerListResult`、`CreateMomentDTO`、`DeleteMomentDTO`、`LikeToggleDTO`、`FollowToggleDTO`、`AddCommentDTO`、`MomentListQuery`、`LikeListQuery`、`PageReq`。
- 广场页：三 Tab（广场/关注/我的）→ `get_moment_list(feed=...)`；图片经 `getFiles(moment.uuid)` 解析，无则跳过媒体区。
- 动态详情页 `/home/moments/:id`：`get_moment_detail(id)` + 图片解析；点赞切换与赞过的人（`get_moment_likers`）；页内评论（`get_moment_comments` 分页 + `post_moment_comment`）；作者本人可删除（`delete_moment`），删除后返回列表。
- 卡片整卡点击进详情；内部点赞/评论/关注/轮播箭头用 `stopPropagation` 隔离，避免误触跳转。

## 11. 后续演进（未落地）

- **评论楼中楼**：`moment_comment` 加 `parent_id / reply_to`，当前为扁平评论。
- **评论点赞**：评论级 `liked_by_me / like_count`，可复用 `moment_like` 结构或独立评论点赞表。
- **删除动态**：已软删实现 `/moment/delete`（仅作者），无需删除接口的讨论；后续如需彻底清理可硬删。
- **超大 feed 性能**：`like_count/comment_count` 为实时相关子查询，量大时可迁移到 Redis 计数或物化计数列。
- **作者冗余快照**：若投影重、压测偏慢，可将 `username/icon` 报名时快照进 `moment`（当前坚持 JOIN）。
