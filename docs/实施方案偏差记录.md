## 3. 其他重要实现约定

- **`rbdc::Uuid` 是 `struct Uuid(String)` 新类型**（非 `uuid::Uuid` re-export），跨边界一律 `to_string()` / `parse()` 转换；其 `FromStr` **不校验**，非法 uuid 必须用 `uuid::Uuid::parse_str` 兜住（否则穿透到绑定层报错）。
- **py_sql 标量解码不可靠**：`max(id)` / `exists` 一类标量查询走 `rb.query` + 手工取值（`entity::models::scalar_i64` / 结果数组非空判断）。
- **keyset 分页游标参数必须显式转型**（`::int2/::int8/::uuid`），且排序键方向与行比较一致（全降序），否则同连接语句缓存 `22P03` / 同 `last_message_at` 漏行。
- **`/session/sync` 返回会话内双向全部消息**（未读归属由客户端按 `recv_user == me` 计算），非「仅我收到的」。
- **客户端本地角标为准**：`/session/list` 刷新只合并 `session_uuid` / `pinned` / 摘要，不覆盖本地 `unread_count`。
- 消息表清理**逐分区用 `ctid` 批删**（任务 09 初版按 `id` 定位，任务 11 因 PK 改为 `(session_uuid, id)` 而重构）；`ctid` 是分区内局部值，**必须逐分区执行**，跨分区会误删。
- **索引写路径优先**（任务 11）：两张消息表从 PK + UK + 多个独立索引压到 **PK + UK 两个约束索引**；热读全部钉在分区键上，PK 以分区键打头并 `INCLUDE` 过滤列（`recv_user`/`timestamp`/`send_user`）。代价：聚合发现（V4）与清理退化为扫描 —— 前者由任务 09 §2.4 LATERAL 解决，后者是日频后台任务可接受。
- **`/session/sync` 契约（任务 12）**：`sessions` 元素对象化（`{ session_uuid, before_id? }`）、删 `mode`（旧字段 serde 静默忽略）；空 `sessions` 返回空响应（不再服务端筛会话）；归属校验失败**静默跳过**；`truncated_by_window` 仅 `!has_more` 时以**纯 `id` 存在性**探测（不依赖 timestamp 单调）。
- **客户端同步语义（任务 12）**：架构不变式 —— **QUIC 只管在线实时投递，离线补齐永远走 HTTP 拉取**（禁止 QUIC 重连推积压）；回填终止条件仅 `!has_more` / `truncated_by_window`（**不用**「零新增」，零新增只证明「这批在本地」）；`hist_floor` 单调只向下，一经建立即长期有效（`backfill=完成` 不再产生新洞）。
