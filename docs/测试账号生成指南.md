# 批量生成测试账号指南

本文说明如何为本项目生成一批可直接登录的测试账号，用于本地联调、功能验证或 API 压测。

## 脚本位置

```
only-talk-rs/scripts/generate_test_accounts.sql
```

> **重要**：该脚本**不能**放进 `crates/entity/ddl/` 目录。`entity::ddl::apply_all_ddl`
> 会递归执行 `ddl/` 下所有 `.sql`，若放入会被集成测试自动运行；且脚本内含 `INSERT`，
> 重复执行会因唯一约束冲突而中断测试。

## 生成内容

一次生成 **200** 个账号，命名规律如下：

| 项   | 样例          | 说明                                     |
|------|---------------|------------------------------------------|
| 账号 | `test_001`    | `basic_user.account`，全局唯一            |
| 用户名 | `测试用户001` | `basic_user.username`                    |
| 邮箱 | `test_001@test.local` | `user_info.email` 与 `email_sso.email`；`email_normalized` 转小写且唯一 |
| 密码 | `Test@12345678` | 所有账号**共用**同一个密码（Argon2id 哈希）|

## 写入的表

| 表             | 关键字段                                                        | 作用           |
|----------------|-----------------------------------------------------------------|----------------|
| `basic_user`   | `uuid`, `account`, `password`(Argon2), `registration_status=1`  | **登录凭证**，`registration_status=1` 才允许登录 |
| `user_info`    | `uuid`, `gender`, `age`, `birthday`, `email`, `created_at` 等   | 用户详情       |
| `email_sso`    | `uuid`, `email`, `email_normalized`(唯一), `verified=true`, `status=1` | 邮箱登录渠道（FK 关联 `basic_user.uuid`） |
| `plaza_user_info` | `uuid`, `allow_discover=true`, `status=0`, `created_at` 等    | 交友广场信息   |
| `user_cache`   | `uuid`, `created_at`, `updated_at`, `version=1`                 | 用户缓存       |

## 使用方法

```bash
# 直接执行（在 only-talk-rs 仓库根目录）
psql -U <用户名> -d <数据库名> -f scripts/generate_test_accounts.sql
```

执行成功后可用接口登录验证，例如 `POST /user/sign_in`，请求体：

```json
{ "account": "test_001", "password": "Ab123456789011", "platform": "PC" }
```

## 关键设计说明

- **明文密码为何不可缺**：登录链路在 `http_service/src/http_service/user_service/service/user_service.rs`
  中用 `verify_password(password, stored_hash)`（Argon2）比对，因此数据库中必须存的是
  Argon2id 哈希而非明文。
- **纯 SQL 无法生成 Argon2 哈希**（哈希带随机盐）。脚本中的 `v_pwd` 常量是预先用仓库自身的
  `common::utils::rsa_util::hash_password` 生成的一份 Argon2id 哈希（明文本为 `Test@12345678`）。
  所有账号复用同一份哈希 **是安全的**：`verify_password` 每次都用同一份盐与明文比对，
  只校验"密码是否匹配"，与盐是否重复无关。
- **需要其他密码怎么办**：不必改脚本，只需重新生成一份哈希并替换 `v_pwd` 常量即可：
  ```text
  # 在 only-talk-rs 根目录临时新建 crates/common/examples/gen_hash.rs 并运行
  cargo run -p common --example gen_hash -- <新密码>
  ```
  将输出替换 `v_pwd`，随后删除该临时示例文件。

## 注意事项

1. `email_sso.email_normalized` 有唯一约束，**同一分库重复执行脚本会报错**。需要重新生成时，
   请先清空相关表（`basic_user`、`user_info`、`email_sso`、`plaza_user_info`、`user_cache`）
   或重建测试数据库。
2. 脚本假定连到目标库的 role 有上述表所在 schema（默认 `public`）的写入权限。
3. 账号命名、总数、密码均可在脚本顶部/循环参数处按需调整。
